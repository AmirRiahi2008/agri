# شناسنامه پروژه‌های کشاورزی و دامپروری

دموی استاتیک فارسی و راست‌به‌چپ برای تابلو مشخصات واحد، نظارت ساخت در چهار مرحله و گزارشات مردمی. طراحی روشن، لوگوی قبلی، فونت وزیرمتن، چیدمان موبایل و انیمیشن‌ها حفظ شده‌اند. پروژه از Tailwind CSS، Alpine.js، Motion و Leaflet استفاده می‌کند.

## اجرای نسخه آماده

داخل پوشه اصلی پروژه اجرا کنید:

~~~bash
python3 -m http.server 8081 --directory dist
~~~

نشانی را باز کنید: http://localhost:8081 . ترمینال را باز نگه دارید؛ توقف با Ctrl+C است. برای اجرای خروجی آماده، npm ci لازم نیست. پوشه dist را می‌توانید روی هاست استاتیک قرار دهید.

برای تغییر استایل و ساخت خروجی جدید:

~~~bash
npm ci
npm run build
npm run check
~~~

## اطلاعات واحد و ناظر

- نمونه فعلی: «احداث واحد مرغداری گوشتی» با نام «مرغداری فخرالدین کشیری».
- تابلو شامل بسمه تعالی، کارفرما، شماره پروانه تأسیس، ظرفیت، تعداد سالن‌ها، مساحت زمین، زیربنای کل، دستگاه نظارت، تاریخ شروع و مدت اجراست.
- فقط یک ناظر ساخت با تخصص مهندسی کشاورزی وجود دارد.
- نام ناظر، پروانه، ظرفیت، ابعاد، تاریخ‌ها، گزارش‌ها و مدارک، داده‌های تستی هستند و مشخصات واقعی یا مجوزهای این مرکز محسوب نمی‌شوند.
- مدارک پرونده شامل نمونه متنی پروانه تأسیس، طرح جانمایی و برنامه زمان‌بندی است؛ پیوست اجرایی واقعی ندارد.

## چهار مرحله گزارش ساخت

1. جانمایی و آماده‌سازی زمین
2. پی و اسکلت سالن‌ها
3. سالن‌ها و تأسیسات
4. بازدید نهایی و جمع‌بندی ساخت

این چهار عنوان برای نمونه فعلی تنظیم شده‌اند و ادعای انطباق با فرم مصوب خاصی ندارند. عنوان‌ها و چک‌لیست‌ها در فایل داده قابل ویرایش‌اند.

دو مرحله اول گزارش نمونه دارند. ناظر با هر شماره موبایل معتبر وارد پنل نمایشی می‌شود. هر مرحله پس از وجود گزارش مراحل قبل باز می‌شود. ثبت گزارش تکمیلی، سوابق قبلی را حفظ می‌کند.

هر گزارش شامل عنوان، تاریخ بازدید، درصد پیشرفت، چک‌لیست همان مرحله، مشاهدات، نتیجه و عکس‌های اختیاری است. نتیجه «نیاز به پیگیری» توضیح اقدام بعدی می‌خواهد. ثبت «بدون مغایرت» نیازمند علامت‌زدن همه موارد بررسی‌شده است. پیش‌نویس‌ها به تفکیک شماره موبایل و مرحله بازیابی می‌شوند.

«تعداد مراحل دارای گزارش» از «درصد پیشرفت فیزیکی» جداست. درصد پیشرفت از تازه‌ترین تاریخ بازدید گرفته می‌شود؛ گزارش تکمیلی با تاریخ بازدید قدیمی آن را عقب نمی‌برد. ثبت هر چهار گزارش، مجوز بهره‌برداری صادر نمی‌کند.

## گزارشات مردمی و عکس

- بدون ورود، نام یا شماره موبایل.
- دو نوع «گزارش تخلف» و «گزارش تشویقی».
- عنوان، متن، عکس‌های اختیاری، بازیابی پیش‌نویس و شناسه ثبت محلی.
- گزارش مردمی به کارشناس ارجاع نمی‌شود و وارد گزارش‌های ناظر یا شمارش مراحل نمی‌شود.
- سوابق خود این مرورگر، متن و عکس‌ها در بخش عمومی قابل مشاهده‌اند؛ خبرخوان عمومی یا ارسال به سازمان دیگری وجود ندارد.

در هر گزارش ناظر یا مردمی می‌توان حداکثر ۳ عکس JPG، PNG یا WebP، هرکدام تا ۸ مگابایت، انتخاب کرد. مرورگر عکس‌ها را برای نگهداری محلی کوچک و به JPEG تبدیل می‌کند. پیش‌نمایش، حذف قبل از ثبت و نمایش بزرگ عکس‌ها وجود دارد.

اطلاعات و عکس‌ها در localStorage همان مرورگر، دستگاه و دامنه‌اند. در صورت کمبود فضا، خطای روشن نمایش داده می‌شود و فرم حفظ می‌شود؛ پیام موفقیت کاذب داده نمی‌شود. پاک‌شدن داده مرورگر، داده‌های محلی را هم حذف می‌کند.

## تغییر نمونه به گاوداری یا مرکز دیگر

فایل dist/assets/project-data.js محل اصلی تغییر داده‌هاست.

| تنظیم | کاربرد |
| --- | --- |
| project.kind | broiler برای مرغداری گوشتی، dairy برای گاوداری شیری، livestock برای پرواربندی |
| project.name / owner | نام واحد و کارفرما |
| project.capacity / spaces | ظرفیت و تعداد سالن یا جایگاه |
| project.landArea / builtArea | مساحت زمین و زیربنای کل |
| project.license / supervisingAgency | شماره پروانه و دستگاه نظارت |
| project.startDate / duration | تاریخ شروع میلادی با قالب YYYY-MM-DD و مدت اجرا |
| project.supervisor | تنها ناظر ساخت پروژه |
| project.location | مختصات، آدرس و منبع موقعیت |
| stages | عنوان و چک‌لیست چهار مرحله |
| seedReports / documents / letters | گزارش‌ها، مدارک و مکاتبات نمونه |

واحد ظرفیت و عنوان سالن/جایگاه از نوع واحد گرفته می‌شوند. اعداد نمونه را هنگام تغییر نوع مرکز متناسب با آن تغییر دهید. با تغییر شناسه project.id، ذخیره محلی پرونده جدید مستقل می‌شود. اطلاعات نسخه ساختمانی قبلی با داده کشاورزی مخلوط نمی‌شود.

## نقشه

Leaflet از OpenStreetMap بدون API Key استفاده می‌کند. سرویس نقشه به اینترنت نیاز دارد. زوم، پین سفارشی، مسیریابی، کنترل دو انگشتی، نمای بزرگ و بازیابی اتصال حفظ شده‌اند.

موقعیت مرغداری فخرالدین کشیری از اطلاعات مکان در [صفحه بلد ارسالی کاربر](https://balad.ir/p/PXW3kWHIxTy5Jx) ثبت شده است. مختصات خود مکان در اطلاعات صفحه با مرکز نمای نقشه در انتهای لینک تفاوت دارد؛ نشانگر از مختصات مکان استفاده می‌کند. آدرس ثبت‌شده در بلد «شهرستان ساری، میدان شهدا» است.

~~~js
location: {
  coordinates: [36.6106937, 53.1022981], // [latitude, longitude]
  address: 'شهرستان ساری، میدان شهدا',
  sourceUrl: 'https://balad.ir/p/PXW3kWHIxTy5Jx',
  zoom: 16
}
~~~

هر سه لینک مسیریابی، پین، عنوان نقشه و نمای بزرگ خودکار از همین داده استفاده می‌کنند. بدون مختصات، پیام انتظار و جستجوی نام مرکز نمایش داده می‌شود و نشانگر ساختگی وجود ندارد. کاشی‌ها آنلاین بارگیری می‌شوند و در بسته پروژه ذخیره نشده‌اند.

## فایل‌ها

| فایل | کاربرد |
| --- | --- |
| dist/index.html | رابط فارسی و قالب‌های Alpine |
| dist/assets/project-data.js | مشخصات واحد، ناظر، مراحل و تمام داده‌های نمونه |
| dist/assets/app.js | گزارش‌های ناظر و مردمی، عکس، پیش‌نویس و ذخیره محلی |
| dist/assets/project-map.js | نقشه Leaflet و مدیریت اتصال |
| src/styles.css | Tailwind و سبک‌های اختصاصی |
| dist/assets/farm.svg | تصویر شماتیک سه سالن مرغداری |
| dist/assets/logo.png | لوگوی قبلی با نوشته «شناسنامه ساختمان» |
| scripts/build.mjs | ساخت CSS و کپی وابستگی‌های محلی |
| scripts/check.mjs | بررسی جریان‌های اصلی در DOM |

این نسخه دیتابیس، API یا احراز هویت واقعی ندارد. ورود آزمایشی محدودیت دسترسی امن ایجاد نمی‌کند؛ اطلاعات پنل در سورس استاتیک موجودند. هیچ گزارش مردمی یا عکس به بیرون ارسال نمی‌شود. هنگام افزودن بک‌اند، مجوز دسترسی و ذخیره فایل باید سمت سرور پیاده شود.

## بررسی و مجوزها

بررسی خودکار شامل داده‌های تابلو، ناظر واحد، چهار مرحله، ترتیب مراحل، پیش‌نویس مستقل، تاریخ و پیشرفت، چک‌لیست، اقدامات پیگیری، سوابق، ورود، گزارش مردمی بدون ورود، عکس، خطای ذخیره، نقشه، ارتباط مجدد و QR است. آزمون نقشه، مختصات واقعی ثبت‌شده از بلد، پین، مرکز نقشه، آدرس و مقصد مسیریابی در نمای اصلی و بزرگ را بررسی می‌کند. سناریوهای اتصال و تعامل موبایل از نقطه مصنوعی مخصوص تست استفاده می‌کنند؛ آن نقطه در داده پروژه درج نمی‌شود.

پردازش عکس در DOM با جایگزین آزمایشی Image و canvas بررسی می‌شود؛ رمزگشایی واقعی فایل و بررسی کامل رابط در مرورگر و دستگاه واقعی در محیط ساخت انجام نشده است.
